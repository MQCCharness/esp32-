# ESP32-S3 开发踩坑记录与操作规范

> 项目：ESP32-S3 MOC 2.0 开发板 · MicroPython 串口 ASCII 动画
> 日期：2026-08-27 · 环境：Win11 + Python 3.12 + esptool v5.3.1 + MicroPython v1.29.0
> 结论先行：**动画链路已跑通（COM4 @115200，≈5.5fps 循环播放），本文沉淀踩过的 7 个坑和对应操作规范。**

## 一、问题与解决对照表

| # | 问题 | 现象 | 根因 | 解决方案 |
|---|------|------|------|----------|
| 1 | USB CDC 串口反复挂死 | COM5（板载 USB）报 `could not enter raw repl` / `may be in use`，重启后仍无响应 | MicroPython TinyUSB CDC 驱动与 Windows 组合不稳定，大流量传输或空闲后易挂 | **改走硬件串口**：板载 CH340K（COM4）直连 UART0，全程稳定；CDC 挂死时用 `esptool --port COM4 --after hard-reset chip-id` 硬复位救活 |
| 2 | `machine.UART(0)` 无法重建 | `OSError: ESP_ERR_INVALID_STATE (uart: call uart_driver_install API first)` | 该固件里 UART0 被 REPL dupterm 占用，不允许重新构造 | **放弃重开串口**，动画改用 `print()` 走 REPL 双终端镜像（USB + UART 同时输出） |
| 3 | 串口写文件被截断 | 逐行 `f.write()` 写出的 main.py 是空文件；paste 模式长行也会断 | UART 接收环形缓冲小，长行/快速连续注入必丢包 | 小文件一律 **趁硬复位后的健康窗口用 mpremote 走 USB CDC 传**；必须走 UART 时用 paste 模式 + ≤48 字节分块 + 0.12s 间隔 |
| 4 | REPL 无响应"假死" | 闲置后串口完全无输出 | REPL 空闲时本来就不主动输出（开机横幅早已错过） | 先发 `\x03\x03`（Ctrl-C）再发 `print(9*9)` 探活；**探活必须两个波特率都试**（main.py 可能改过波特率） |
| 5 | 视频源下载受阻 | B 站 API SSL EOF（VPN 出口被风控）；YouTube 数据段 403 | 网络：代理出口 IP 被墙内外服务双重拒绝 | B 站走直连 curl、YouTube 走代理 `--extractor-args "youtube:player_client=android,web_safari,tv"` 换客户端重试；下载格式用 `-f worst`（转 ASCII 不需要高清） |
| 6 | Windows 路径双标 | python 脚本内 `/g/...` 报 FileNotFoundError | Git Bash 只转换**命令行参数**里的 POSIX 路径，字符串内不转换 | 内嵌字符串一律写 `G:/...`；bash 变量传参可用 POSIX 路径 |
| 7 | 带宽吃紧 | 80×22 帧想跑 10fps，串口只有 115200 | 115200bps ≈ 11.5KB/s，一帧 2KB → 上限 ≈5.6fps | 接受 print 阻塞自动节流 → **5.5fps 慢动作播放**；要更快需换 460800+ 或缩小帧（此为体验取舍，不是故障） |
| 8 | **打开串口后 REPL "集体假死"** | CH340K 口打开后两个 USB 通道全静默，芯片似乎不启动；MicroPython 明明在 Flash 里 | **pyserial 打开时 `dtr=True` 经 CH340K 自动烧录电路把芯片摁在复位/下载态**；且空闲 REPL 对 Ctrl-C 不回显提示符，探活方式不对会误判死亡 | **打开串口一律 `dtr=False; rts=False`（中性电平）**；探活发**空回车**（空闲 REPL 会回显 `>>>`），Ctrl-C 只用于打断运行中的脚本；已死机时 `esptool --port COM4 --after hard-reset chip-id` 复活 |
| 9 | 板载 WS2812 不亮（未结案） | 丝印 RGB(48)=GPIO48，时序/电平/寻址全试过仍不亮 | 疑似 WS2812 供电挂在外部电源/电池轨（板有"电源接口"6-9V 输入 + OFF/ON 开关 + 7.4V 电池口），USB 逻辑供电不含灯的电；或器件本体损坏 | 软件侧证据已闭环（丝印实拍+GPIO0 按键电气实证+全部时序矩阵），需背面走线照片或插外部电源才能继续；**教训：教育板的"表演型外设"常挂独立供电轨，先查供电再怀疑代码** |

## 二、标准操作规范（SOP）

### 2.1 烧录/恢复固件

```bash
# MicroPython 固件（当前在线）
python -m esptool --port COM4 --baud 460800 write-flash 0x0 ESP32_GENERIC_S3-vX.X.X.bin
# 出厂固件（仓库 one_click_restore/ 一键包，或手动）
python -m esptool --port COM3 --baud 921600 write-flash 0x0 factory_full_4M.bin
```

- 板子有两条物理通道：**USB 原生口**（COM3/COM5，随固件变）和 **CH340K 硬件串口**（COM4，永远在）
- **COM4 是救命通道**：USB 侧无论怎么挂，esptool 走 COM4 都能硬复位进下载模式
- 烧录报 `Packet content transfer stopped`：USB 缓冲停滞，降低波特率或分小块重试即可

### 2.2 传文件到板子（重要度排序）

1. **首选**：硬复位后 2 秒内，`python -m mpremote connect COM5 cp 本地文件 :目标文件`（CDC 健康窗口内，小文件秒传）
2. **备用**：`mpremote connect COM4 cp ...`（UART@115200，慢但稳，⚠️ mpremote 默认波特率匹配时才可用）
3. **禁止**：向 REPL 逐行灌长命令写文件（坑 #3）

### 2.3 看动画

- 双击 `caixukun_ascii/启动动画.bat`（自动找 COM4）或 `python viewer.py [COM口] [波特率]`
- 动画占住 REPL 时，在 COM4 发 Ctrl-C 即可打断进调试
- 板子**上电自动开播**；想静默开机：删掉板上的 `main.py`（保留 `dance.py` 之类手动运行）

### 2.4 板端调试

- 探活：`python -m mpremote connect COMx exec "print(1+1)"`
- REPL 无响应 → 先 Ctrl-C → 再两个波特率各试一次 → 还不行 → esptool 硬复位
- 文件系统容量查询：`mpremote connect COMx exec "import os; s=os.statvfs('/'); print(s[0]*s[2]//1024, 'KB free')"`

### 2.5 换视频重做帧包

```bash
python -m yt_dlp --proxy http://127.0.0.1:17891 --extractor-args "youtube:player_client=android,web_safari,tv" -f worst -o cxk_source.mp4 "<视频URL>"
# 编辑 convert_to_ascii.py 顶部 SRC/SS/T 参数，然后：
python convert_to_ascii.py        # 产出 frames.bin，打印 N 和 REC
# 同步修改 main.py 顶部 REC/N 常量 → 上传两个文件 → soft-reset
```

- ⚠️ 版权边界：**视频源和转换出的 frames.bin 只留本地，不上传公开仓库**；仓库只放代码
